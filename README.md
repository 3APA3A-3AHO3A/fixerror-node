# fixerror-node

Русский | [English](README.en.md)

Установщик ноды Remnawave для FixErrorVPN. Ставит ноду по общему образцу всех нод сервиса:
- учётка и харденинг SSH, отдельная учётка для ИИ-агентов;
- фаервол с блокировкой торрентов, fail2ban;
- общий шаблон sysctl, замер и закрепление MTU, время UTC;
- Docker и контейнер ноды с geo-базами Loyalsoldier, базы обновляются раз в 3 дня;
- выходы для Xray: WARP на порту 6000, warp-native, Psiphon;
- nginx с сайтом утилит;
- **node-pull**: сертификат и сайт нода забирает с панели;
- уведомления в Telegram через `remnawave-notify`.

Один скачанный файл закрывает весь жизненный цикл ноды: установка, диагностика, точечная починка.

Устройство (tmux, ожидание apt, проверки SSH, меню, диагностика, починка, тесты) взято из [rabotahrista](https://github.com/3APA3A-3AHO3A/rabotahrista). Отличается то, что у нод FixError своё: сертификат с панели вместо Let's Encrypt, `remnawave-notify`, общий шаблон настроек.

## Установка

```bash
sudo curl -fsSL https://raw.githubusercontent.com/3APA3A-3AHO3A/fixerror-node/main/setup.sh -o /tmp/setup.sh
sudo bash /tmp/setup.sh
```

Перед установкой лучше сделать полное обновление системы с перезагрузкой. Установщик и сам обновит пакеты, но новое ядро встанет только после перезагрузки.

Нужны права root. `sudo bash <(curl ...)` не работает: sudo закрывает лишние файловые дескрипторы.

Скрипт задаёт все вопросы сразу, потом работает молча. Если оборвётся SSH, установка продолжается в tmux; вернуться к ней — `sudo tmux attach -t fixerror`. В конце скрипт печатает отчёт и сохраняет его в `/root/node-install-report.txt`.

Без вопросов, с файлом ответов (образец — [config.example.conf](config.example.conf)):

```bash
sudo bash /tmp/setup.sh /root/node.conf
```

## После установки: ключ ноды на панели

Сертификат `*.safeline24.com` и сайт утилит лежат на панели в наборе `/var/lib/node-pull/bundle.tar.gz`. Нода забирает его по SSH своим ключом. Ключ создаёт установщик, а строку с ним на панель добавляете вы — в отчёте она уже готова:

```bash
# на панели
echo 'restrict,from="IP_НОДЫ",command="/bin/cat /var/lib/node-pull/bundle.tar.gz" ssh-ed25519 AAAA... node-pull Finland 3 hshp' \
  | sudo tee -a /var/lib/node-pull/.ssh/authorized_keys
# на ноде
sudo node-pull        # → «обновлено: сертификат сайт»
```

Строка разрешает ровно одно: забрать набор, и только с IP этой ноды. До её добавления nginx работает с временным самоподписанным сертификатом. Дальше таймер `node-pull.timer` проверяет набор раз в 6 часов и после загрузки сервера и ставит обновления сам. Строку заново покажет меню, пункт 2 → 22.

Ключ сервера панели установщик спрашивает у самой панели и печатает его отпечаток. Сверьте его на панели: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Чтобы не сверять, впишите ключ в `PANEL_HOSTKEY` файла ответов.

## Главное меню

| Пункт | Что делает | Меняет систему |
|---|---|---|
| 1. Полная установка | Все шаги подряд, в конце перезагрузка | Да, всё |
| 2. Компоненты | Один шаг на выбор | Да, выбранный |
| 3. Диагностика | Проверяет ноду и печатает список проблем | Нет |
| 4. Починка | Показывает план, спрашивает, чинит типовые поломки | Да, после подтверждения |
| 5. Диагностика + панель | То же, что 3, плюс проверка, отдаёт ли панель набор этой ноде | Нет |

То же без меню:

```bash
sudo bash /tmp/setup.sh --check     # диагностика
sudo bash /tmp/setup.sh --repair    # починка без вопросов
```

Отдельный файл только с диагностикой — `check.sh`. Он заведомо ничего не меняет: это проверяется тестом.

### Чем починка отличается от установки

Полная установка ставит всё заново: сбрасывает правила ufw, пересоздаёт контейнер и уходит в перезагрузку. Поверх работающей ноды её запускать не нужно.

Починка идёт по закрытому списку. Сначала печатает план, потом ждёт ответа: `y` — всё, `s` — по шагам, `N` — отмена.
- права 600 на файлы с секретами: ответы, токен Telegram, ключ node-pull, ключ сертификата, compose;
- харденинг SSH — только если `sshd -T` показывает, что root или пароли открыты;
- группа docker у админ-учётки;
- `remnawave-notify`, его служба, `@reboot` и строка PAM;
- скрипт и таймер node-pull;
- скрипт и таймер geo-update.

Фаервол, контейнер и конфиг сайта nginx починка не трогает и сервер не перезагружает.

## Что ставится

| Что | Как |
|---|---|
| SSH | `/etc/ssh/sshd_config.d/00-hardening.conf`: порт 8422, root и пароли закрыты. Port пишется, только если его нет в основном `sshd_config`: два одинаковых Port дают «Address already in use» |
| UFW | 8422/tcp (limit), 80/tcp, 443/tcp, 443/udp; 2222/tcp только с IP панели; + `UFW_EXTRA_PORTS` |
| Торренты | 6 правил `-m string` в `/etc/ufw/before.rules`, до ESTABLISHED |
| fail2ban | sshd: 4 попытки → бан на 24 часа; recidive: бан на неделю |
| sysctl | `/etc/sysctl.d/99-vpn-tune.conf`: BBR/fq, буферы 16 МБ, conntrack 262144, резерв портов 8422, 2222, 9443, 6000, IPv6 выключен |
| MTU | путь замеряется пингом без фрагментации; если меньше 1500 — служба `mtu-<интерфейс>` и тот же MTU в `daemon.json` |
| Docker | `daemon.json`: ротация логов 10 МБ × 3; журнал systemd — до 1 ГБ |
| Нода | `/opt/remnanode/docker-compose.yml`, network_mode host, базы томами из `/opt/remnanode/geodata` |
| Geo-базы | `/usr/local/sbin/geo-update` + `geo-update.timer`: раз в 3 дня в 01:00 UTC (04:00 МСК) ± 15 минут; проверка sha256; нода перезапускается, только если базы изменились |
| Сайт | Reality: `stub.conf` (self-steal на 127.0.0.1:9443, PROXY protocol). CDN: `<домен>.conf` (443, сайт + XHTTP в Xray) |
| node-pull | `/usr/local/sbin/node-pull`, ключи в `/etc/node-pull`, `node-pull.timer` |
| Уведомления | `/usr/local/sbin/remnawave-notify` (тот же скрипт, что на панели), `/etc/remnawave-notify.env`, `remnawave-notify-watch.service`, `@reboot`, PAM |
| Время | UTC, chrony |

Свой xray для Telegram на нодах в РФ установщик не ставит. Если он нужен, укажите его адрес в `TG_PROXY`.

## Разработка

`setup.sh` и `check.sh` в корне руками не редактируются — это собранные файлы. Исходники лежат в `lib/`, сборщик `build.py` склеивает их по алфавиту имён.

| Модуль | Что внутри |
|---|---|
| `00-header.sh` | режимы оболочки, обработчик ошибок, все настройки |
| `05-ui.sh`, `06-spinner.sh` | оформление и живая строка шага |
| `07-probes.sh` | только читающие проверки, общие для установки и диагностики |
| `10-helpers.sh` | шаги и итоговый отчёт |
| `20-prompts.sh` | все вопросы и проверка введённого |
| `30-state.sh` | сохранение ответов, вычитывание настроек с ноды |
| `40-system.sh` | swap, пакеты, sysctl, время, MTU, диск, автообновления |
| `45-preflight.sh` | проверки сервера, cloud-init и apt, tmux, замок |
| `50-security.sh` | учётки, ключи сервера, SSH, UFW и торренты, fail2ban |
| `60-node.sh` | Docker и контейнер ноды |
| `62-geodata.sh` | geo-базы и их таймер |
| `70-web.sh` | сайт nginx и node-pull |
| `80-notify.sh` | remnawave-notify |
| `85-extras.sh`, `86-egress.sh` | WARP, Speedtest, warp-native, Psiphon |
| `90-install.sh` | порядок шагов полной установки |
| `92-repair.sh`, `94-check.sh` | починка и диагностика |
| `95-menu.sh`, `99-main.sh` | меню и точка входа |

Рабочий цикл:

```bash
git config core.hooksPath .githooks   # один раз
# правите модуль в lib/
git add -A
git commit -m "..."                   # хук соберёт setup.sh и check.sh и прогонит тесты
git push
```

Тесты: `bash tests/run-tests.sh`, сервер не нужен. Кроме синтаксиса и shellcheck, они проверяют:
- шаблоны sysctl, SSH и торрентов;
- конфиг сайта для обеих ролей и откат, если nginx -t не прошёл;
- строку ключа для панели;
- что `remnawave-notify` совпадает байт в байт с эталоном `tests/remnawave-notify.ref`;
- безопасное обновление geo-баз;
- что диагностика ничего не меняет.

Если `remnawave-notify` меняется на панели, обновите и эталон, и `lib/80-notify.sh`.
